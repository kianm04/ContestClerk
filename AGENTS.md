# MUNMeet

A platform for Model United Nations conferences. The web client is `client/`: SvelteKit 2,
Svelte 5 runes, TypeScript, Tailwind 4, pnpm, with a local Supabase in Docker. `README.md`
has the product notes and `client/src/routes/styleguide/` shows the components and tokens.
`docs/DESIGN.md` locks down how the site looks: read it before any work that changes what
a person sees. The UI is moving to shadcn-svelte; `client/src/lib/components/ui/` and
`client/src/lib/utils.ts` are generated by its CLI, never edited by hand, and exempt from
the rules below.

## How to write code here

- Teammates learning Svelte will read every line. Write obvious code with full names
  (`conference`, `handleSubmit`, `isOpen`) and comment the why, not the what.
- Explain a Svelte or SvelteKit mechanism a newcomer would not know the first time a file
  uses it: `$props`, `$derived`, `load` data, `{#each}` keys, `$lib/server`, `resolve()`.
- Keep components small and flat: one visible thing each, under about 100 lines, logic in
  `$lib/*.ts`, data access in `$lib/server/*.ts`, server-only code nowhere else.
- Runes only. Prefer `$derived` over `$effect`. Avoid snippets, actions, transitions and
  context unless there is no other way; `use:enhance` with `createInPlaceForm()` is the
  one sanctioned action for forms.
- List and filter pages keep their state in the URL and load it in `+page.server.ts`.
  Forms work without JavaScript first. Colour and type come from shadcn variants and the
  theme variables; Tailwind classes in the markup are for layout.
- Make the smallest change that completes the task. Say so before adding a dependency.
  Schema changes are new migrations with database tests, never edits to applied ones.

## Rules
- Before doing any form of frontend work, always read the @docs/DESIGN.md file.

## Before you finish

Run `pnpm verify` from `client/` and fix what it reports. `pnpm house-rules` alone lists
the rules a script checks. `pnpm verify` leaves out the browser tests, so run the ones for
pages you touched by path, for example `pnpm test:e2e tests/e2e/home.spec.ts`.

## Extra info
- When the user mentions Trello, the board, or issues, tickets or cards, invoke the
`trello-card` skill with their words as the arguments before looking anything up yourself.
- Previously this codebase had a specs/ folder, this folder no longer exists, some pieces of code may still reference it.
